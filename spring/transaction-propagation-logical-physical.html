1꼬리질문 9 — 안쪽에서 난 예외를 바깥에서 잡으면 ①②는 commit될까?

class PointNotEnoughException : RuntimeException("포인트 부족")

@Service
class PointService {
    @Transactional                                   // 기본 전파 = REQUIRED
    fun use(userId: Long, amount: Int) {
        throw PointNotEnoughException()
    }
}

@Service
class OrderService(...) {
    @Transactional
    fun order(userId: Long, productId: Long) {
        stockRepository.decrease(productId)          // ①
        orderRepository.save(Order(...))             // ②
        try {
            pointService.use(userId, 1000)           // ③ 다른 빈 → 프록시 거침
        } catch (e: PointNotEnoughException) {
            log.warn("포인트 부족, 주문은 진행")       // 잡았으니 order()는 정상 종료
        }
    }
}
내 답변 (원문)
"1,2 는 커밋될거같아. 왜냐하면 해당건을 RuntimeExecption으로 잡았지만. runtime익셉션이 발생했을때 warn 만 남기겠다고 catch할때 해놨으니. 해당 스택 트레이스가 정상적으로 그냥 끝나게 할거같아. 그럼으로 1 2 는 커밋된다"
❌ 오답 — 바깥 프록시만 봤다. 안쪽 프록시(PointService)가 빠짐

①② 모두 rollback되고 UnexpectedRollbackException이 던져져 500 응답.

안쪽 프록시가 예외를 보고 공유 트랜잭션에 🚩 rollback-only 표시를 남긴다. 바깥이 예외를 삼켜도, 커밋하려는 순간 그 표시 때문에 롤백된다.
내 답이 맞는 조건: use()에 @Transactional이 없을 때 → 아래 "use()에 @Transactional 없으면" 버튼

3논리 트랜잭션은 언제 생기나? → @Transactional 프록시를 지날 때마다

@Transactional 프록시 진입
= 논리 트랜잭션 1개 생김
►
내 스레드의 사물함에
트랜잭션이 이미 있나?
►
없음 → 새 물리 트랜잭션 시작 (주인)
있음 + REQUIRED (기본) → 기존 물리에 참여 (손님)
있음 + REQUIRES_NEW → 기존 것을 빼 두고 새 물리
있음 + NESTED → 같은 커넥션에 세이브포인트
스레드는 "프록시가 기존 트랜잭션을 볼 수 있나"를 정합니다 (사물함 = ThreadLocal).
전파 속성은 "봤다면 참여할지, 새로 만들지"를 정합니다.
스레드 수와 논리 트랜잭션 수는 관계없습니다. 아까 runAsync는 스레드가 바뀐 것이고, 지금은 같은 스레드에서 프록시를 두 번 지난 것이에요.

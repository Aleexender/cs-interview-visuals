self-invocation: 같은 클래스에서 부르면 @Transactional이 무시되는 이유

2026-10-15 모의면접 꼬리질문 11 · "어노테이션이 붙어 있다 ≠ 적용된다"

1질문 · 내 답 · 판정

@Service
class OrderService(...) {
    @Transactional
    fun order(userId: Long, productId: Long) {
        stockRepository.decrease(productId)   // ①
        orderRepository.save(Order(...))      // ②
        try { use(userId, 1000) }             // ③ 같은 클래스의 메서드 (= this.use())
        catch (e: PointNotEnoughException) { log.warn("포인트 부족") }
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    fun use(userId: Long, amount: Int) { throw PointNotEnoughException() }
}

Q1. REQUIRES_NEW가 적용되나? 이유는?   Q2. 커넥션은 몇 개? ①②는 commit되나?

내 답변 (원문)
"1. 적용 되지. 왜냐하면 propagation.requires_new를 작성했으니까
2. 2개"
❌ 둘 다 오답 (깊이 0). 1번 근거는 순환논법(썼으니까 적용된다), 2번은 근거 없음 + ①② 질문 미답
정답
1. 적용되지 않는다. use()를 this로 불러서 프록시를 거치지 않기 때문. 어노테이션을 읽고 처리하는 건 프록시인데, 프록시가 끼어들 틈이 없다.
2. 커넥션 1개. ①②는 commit — 하지만 "REQUIRES_NEW라서"가 아니라 "use()가 그냥 order()의 일부로 실행돼서".
08-05 돌발 질문(self-invocation)에서 0 → 2로 올랐던 노드가 다시 0. 판별 습관: @Transactional · @Async · @Cacheable을 보면 "이 호출이 프록시를 거치나?"를 먼저 묻는다.

@Transactional은 어노테이션이 일하는 게 아니라 프록시가 일합니다. 어노테이션은 "프록시야, 여기 오면 이렇게 해 줘"라는 메모일 뿐이에요.
this는 프록시가 아니라 진짜 객체 자신이라, 진짜 객체 안에서 자기 메서드를 부르면 껍데기(프록시)를 다시 지날 일이 없습니다 → 메모를 읽을 사람이 없음.

3단계별 비교 — 포인터로 따라가기

4고치는 방법

① 다른 빈으로 분리 (권장)
@Service
class PointService {
    @Transactional(propagation = REQUIRES_NEW)
    fun use(...) { ... }
}
// OrderService에서
pointService.use(userId, 1000)   // 프록시 경유
트랜잭션 경계가 다르면 책임도 다르다는 신호. 구조로 해결.
② TransactionTemplate (코드로 경계 지정)
private val newTx = TransactionTemplate(txManager).apply {
    propagationBehavior = PROPAGATION_REQUIRES_NEW
}
fun use(...) = newTx.execute { ... }
프록시 없이 직접 트랜잭션을 연다. 같은 클래스에 둬야 할 때.
③ 자기 자신의 프록시를 주입
class OrderService(
    @Lazy private val self: OrderService,
) { ... self.use(userId, 1000) ... }
동작은 하지만 "자기 자신을 주입"은 설계 냄새. 최후의 수단.
같은 함정에 빠지는 것들
프록시로 동작하는 어노테이션 전부:
@Transactional · @Async · @Cacheable · @Retryable
→ 같은 클래스 안에서 this로 부르면 전부 무시됩니다.
면접용: "@Transactional은 프록시가 처리하기 때문에 같은 클래스 안에서 this로 호출하면 프록시를 거치지 않아 전파 속성을 포함한 트랜잭션 설정이 전부 무시됩니다. 그래서 트랜잭션 경계가 다른 메서드는 별도 빈으로 분리합니다."

@PostConstruct는 왜 프록시를 안 거치나 — 3D로 호출 따라가기

2026-10-26 모의면접 Q1-8 · 공(●)이 "호출"입니다. 공이 보라색 껍데기(프록시 @2)의 입구(게이트)를 지나면 트랜잭션이 걸리고, 안 지나면 안 걸립니다.
@Transactional은 메서드에 붙는 기능이 아니라, 프록시 @2의 게이트를 통과한 호출에만 걸리는 기능이다.

Q1-8 코드의 결과—findAll() 뒤 영속성 컨텍스트 닫힘 → category.name에서 LazyInitializationException → 기동 실패—
// @PostConstruct를 부르는 스프링 코드 (단순화) — CommonAnnotationBeanPostProcessor
Object postProcessBeforeInitialization(Object bean) {   // bean = @1 (원본). @2는 아직 세상에 없음
    for (Method m : @PostConstruct 메서드들) m.invoke(bean);   // → @1.warmUp() 직접 호출
    return bean;
}
면접용: "@PostConstruct는 BeanPostProcessor의 초기화 전 단계에서 컨테이너가 원본 객체에 직접 호출하고, 트랜잭션 프록시는 그 뒤 postProcessAfterInitialization에서 만들어지기 때문에 @Transactional이 적용되지 않습니다. 기동 시 트랜잭션이 필요한 작업은 ApplicationReadyEvent 리스너나 TransactionTemplate으로 합니다."

빈 생성과 프록시 바꿔치기: 원본은 언제, 누가 프록시로 바꾸나

2026-10-26 모의면접 꼬리질문 Q1-3 · "컨트롤러가 받은 건 프록시인데, 컨테이너는 원본을 만들었다. 그 사이에 무슨 일이?"

1질문 · 내 답 · 판정

@Service
public class OrderService {
    @Transactional
    public void order(Long itemId) { ... }
}

@RestController
@RequiredArgsConstructor
public class OrderController {
    private final OrderService orderService;   // ← 여기에 든 건 무엇?
}

Q1-3. 컨테이너는 리플렉션으로 원본 OrderService를 만든다. 그런데 컨트롤러가 받은 건 프록시다. 원본이 프록시로 바뀌는 일은 빈 생성 과정의 어느 시점에, 누가 하나? 컨테이너에 등록되는 건 어느 쪽인가?

내 답변 (원문)
"이건 잘 모르겠어"
❌ 모름 (깊이 0). 직전 Q1-2에서 "필드에 든 건 프록시"는 정답 — 무엇은 알고 언제·누가를 모름
정답
초기화가 끝난 직후(⑤), BeanPostProcessor인 Auto Proxy Creator가 원본을 감싼 프록시를 반환한다. 컨테이너는 반환받은 객체를 등록하므로 저장소에는 프록시가 들어가고, 원본은 프록시 안의 target으로만 남는다.

2단계별로 따라가기 — 원본 @1과 프록시 @2

왼쪽 = 빈 하나가 만들어지는 조립 라인. 오른쪽 = 지금 작업대 위의 객체 · 싱글톤 저장소 · 컨트롤러 필드. 보라 칸 = 바꿔치기가 일어나는 지점. 노란 테두리 = 이번 단계에 바뀐 것. ← → 키.
🏭 조립 라인 — OrderService 빈 하나의 일생
🛠 작업대 — 지금 손에 든 객체
📦 싱글톤 저장소 (이름 → 객체)
🎮 OrderController.orderService 필드

🙋
꺼내 가는 사람
컨트롤러는 상자를 받음
헷갈리는 말정확한 말
"프록시는 가짜 객체"프록시는 원본을 품고 앞뒤를 감싸는 객체. 원본도 실제로 만들어지고 비즈니스 로직은 원본이 실행한다
"컨테이너가 처음부터 프록시를 만든다"먼저 원본을 만들고 초기화까지 끝낸 뒤 ⑤에서 감싼다
"컨테이너가 바꿔치기한다"바꾸는 건 BeanPostProcessor(Auto Proxy Creator). 컨테이너는 반환받은 것을 등록할 뿐
"@Transactional이 트랜잭션을 연다"어노테이션은 메모. ⑤에서 그 메모를 보고 프록시를 만들지 결정하고, 호출 시 프록시 → TransactionInterceptor → PlatformTransactionManager가 연다
면접용: "스프링은 기동 시점에 빈을 만들 때, 원본 객체를 생성하고 의존성 주입과 초기화를 마친 뒤 BeanPostProcessor의 postProcessAfterInitialization 단계에서 Auto Proxy Creator가 @Transactional 같은 Advisor가 적용되는지 확인합니다. 적용 대상이면 원본을 감싼 프록시를 반환하고, 컨테이너는 그 프록시를 빈으로 등록하므로 주입받는 쪽은 모두 프록시를 받습니다."

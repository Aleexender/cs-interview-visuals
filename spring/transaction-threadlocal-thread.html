2답: 스레드마다 하나씩 있는 사물함(ThreadLocal)

톰캣은 요청 하나를 스레드 하나에 맡깁니다. ①②③은 같은 스레드가 위에서부터 차례로 실행해요. 그래서 그 스레드 전용 사물함에 커넥션을 넣어 두면 누구든 꺼내 쓸 수 있습니다.

6프록시는 무엇을 보고 commit/rollback을 정하나

// 프록시 내부 (단순화)
try {
    target.order(...)     // ← exec-7의 이 호출에서 예외가 튀어나오나? 이것만 본다
    commit()
} catch (e: RuntimeException) {
    rollback()
}
같은 스레드에서 예외
③ 💥 → order() 스택을 타고 위로 → 프록시 catch에 도착 → rollback
다른 스레드(worker-3)에서 예외
worker-3 스택에서만 올라가 Future에 담김 → exec-7의 order()는 정상 반환 → 프록시 commit
Q7에서 쓴 근거 "서로 다른 커넥션이라서" ❌ → 커넥션은 JDBC 층, 예외 전파는 JVM 호출 스택 층.
반례: worker-3이 같은 conn#42를 썼다 해도 예외는 exec-7로 안 올라오니 프록시는 똑같이 commit합니다 → 커넥션은 근거가 아님.
면접용: "예외는 발생한 스레드의 호출 스택으로만 전파됩니다. 다른 스레드의 예외는 기다리지 않는 한 트랜잭션 프록시에 도달하지 못해서 원래 트랜잭션은 커밋됩니다."

JPA가 요구하는 두 조건을 둘 다 어긴다.
① 인자 없는 생성자가 없다 → Hibernate가 객체를 못 만든다 (에러)
② 클래스가 final이다 (kotlin-spring은 @Entity를 안 연다) → LAZY용 프록시를 못 만든다 → 즉시 조회로 바뀜

2JPA가 엔티티 클래스에 요구하는 것 두 가지 — 왜 필요한가

① 인자 없는 생성자 (public 또는 protected)

Hibernate는 DB 행을 객체로 만들 때 "일단 빈 객체를 만들고 → 필드를 하나씩 채우는" 방식을 씁니다. 생성자 파라미터에 무엇을 넣어야 할지 Hibernate는 모르기 때문이에요.
DB 행→new Post()→id = 1→title = "hi"→author = ?
Kotlin class Post(val author: Author, val title: String)에는 Post(Author, String) 생성자 하나뿐. new Post()를 부를 수 없다.

② final이 아닐 것 (클래스 · 메서드)

LAZY는 "진짜 Author 대신 Author를 상속한 프록시 클래스의 객체를 끼워 두고, 처음 쓸 때 SELECT" 하는 방식입니다. 오늘 Q1-4~5의 CGLIB와 같은 원리 — 상속이에요.
Author← extends ←Author 프록시(id=7만 가짐, 나머지 비어 있음)
Kotlin은 기본이 final. kotlin-spring이 여는 목록(@Component, @Transactional …)에 @Entity는 없다. → Author는 final → 상속 불가.

4정리 — 플러그인이 각각 해 주는 일

설정대상해 주는 일안 해 주는 일
kotlin("plugin.spring")@Component 계열 · @Transactional · @Async · @Cacheable …클래스 · 메서드를 open으로@Entity는 대상 아님
kotlin("plugin.jpa")@Entity · @Embeddable · @MappedSuperclass인자 없는 생성자 생성 (①)open은 안 해 줌 ← 가장 흔한 착각
allOpen { annotation(...) }직접 지정한 어노테이션클래스 · 메서드를 open으로 (②)—
plugins {
    kotlin("plugin.spring")
    kotlin("plugin.jpa")
}
allOpen {
    annotation("jakarta.persistence.Entity")
    annotation("jakarta.persistence.MappedSuperclass")
    annotation("jakarta.persistence.Embeddable")
}

면접용: "JPA 엔티티는 Hibernate가 리플렉션으로 빈 객체를 만들 수 있도록 인자 없는 생성자가 필요하고, 지연 로딩 프록시가 엔티티를 상속하므로 final이면 안 됩니다. Kotlin은 둘 다 기본으로 어기기 때문에 plugin.jpa로 생성자를 만들고, allOpen으로 @Entity 클래스를 open으로 엽니다."
